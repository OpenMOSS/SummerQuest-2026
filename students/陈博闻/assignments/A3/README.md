> 本报告仅包含公开、脱敏的实验摘要。正式实验通过课程 API 完成；报告不包含 API
> 地址、凭据、内部路径、训练数据、模型权重或完整服务日志。

## 基本信息

- 完成范围：完成 API 工作流验证、学习率初筛、五档真实 IsoFLOPs 实验、参数与 loss
  scaling-law 拟合、拟合敏感性分析、wall-clock 建模，以及代理模型和最终架构上的
  batch/LR 稳定性验证；已提交一组 48 official accelerator-hours 最终配置和 loss 预测。
- 未完成项：没有取得 `2.0e17 FLOPs` 高计算锚点的完成 loss；没有用独立重复种子校准预测

- 探索预算使用情况：正式预算为 43,200 秒，最终计费 41,542 秒，剩余 1,658 秒。共记录
  47 个探索实验，其中 44 个完成、3 个失败；一次确认的失败运行所占 9,000 秒后来由课程端
  返还，因此不计入最终已用预算。

## 1. 实验设计

### 1.1 总体策略

我把有限预算分成五个阶段，而不是直接搜索一个大模型：

1. 先用作业提供的合成 IsoFLOPs 数据检查分组、谷底选择、幂律拟合和外推代码；合成数据
   只用于验证方法，不作为课程 API 训练结果。
2. 用 smoke test、短运行和小模型学习率扫描验证 schema、计费、持续吞吐和基本收敛行为。
3. 在约 `4.04e14` 到 `1.03e17 FLOPs` 间按约 4 倍间隔设计五个真实 IsoFLOPs profile；
   每档改变模型规模和训练 token，并让同档计算量尽量一致，以定位 compute-optimal 模型规模。
4. 尝试在 `2.0e17 FLOPs` 增加高计算锚点，并建立 wall-clock 模型，将 FLOPs 最优与
   48 小时内实际可运行区分开。
5. 锚点失败且预算返还后，不再补低算力曲线，而是在代理模型和最终候选架构上做 batch/LR
   对照，直接降低最终配置的训练稳定性和超时风险。

主线实验保持 sequence length 1024、AdamW、cosine decay、5% warmup、final LR fraction
0.1、weight decay 0.01 和 4 次 validation evaluation。早期 IsoFLOPs 主线使用 batch 4；
batch 与学习率只在最后的专门对照中改变。

### 1.2 纳入和排除规则

- 只有状态为 `completed` 的最终 validation loss 才能作为普通观测。
- IsoFLOPs 参数拟合只使用五档等算力 profile；smoke、学习率、batch 和稳定性实验各自用于
  对应诊断，不混入 compute-optimal 谷底拟合。
- 失败运行的 partial loss 不作为 completed loss。三条失败记录分别是：`exp-000167`
  （初始吞吐探测）、`exp-000278`（第四档右侧点，只返回一次 partial loss）和
  `exp-000377`（高计算锚点，超过运行时间上限且没有返回 loss）。
- 最后一个 profile 的 loss 在测量区间右端仍缓慢下降，因此将该档标为
  endpoint-censored；二次曲线顶点只作为敏感性估计，不把它称为被精确包围的谷底。

## 2. 主要结果与 Scaling-law 拟合

### 2.1 五档 IsoFLOPs 结果

下表的 `N` 均为非 embedding 参数量；计算量采用课程 API 给出的统一估计。`连续 N_opt`
由谷底附近的 `log(N)` 二次拟合得到。第五档因端点删失，使用全局二次顶点作为中心估计，
同时保留宽平台风险。

| 计算档 | 完成点 | 连续 `N_opt` | 离散最佳实验 | 离散最佳 `N` | Tokens | 最佳 loss |
| ---: | ---: | ---: | --- | ---: | ---: | ---: |
| `4.039e14` | 7/7 | 1.269M | `exp-000238` | 1.328M | 6.111M | 12.169434 |
| `1.617e15` | 5/5 | 1.919M | `exp-000243` | 2.410M | 19.661M | 10.982910 |
| `6.466e15` | 5/5 | 4.379M | `exp-000257` | 4.980M | 55.247M | 9.602295 |
| `2.586e16` | 4/5 | 6.477M | `exp-000276` | 6.148M | 193.430M | 8.689453 |
| `1.034e17` | 5/5 | 23.339M | `exp-000375` | 31.860M | 283.050M | 7.910645 |

前四档基本形成可辨认的 U 型。第五档从 16.620M 增至 31.860M 非 embedding 参数时，
loss 只改善 0.01392，说明 20M--32M 附近更像宽平台，而不是能精确确定的单一最优点。

对五个连续最优点在 log space 拟合：

$$
N_{\mathrm{opt}}(C)=0.0410493\,C^{0.507774},
$$

其 log-space $R^2=0.959051$。这里的 `N` 是非 embedding 参数，而 API FLOPs 使用包含
embedding 的完整计算口径；因此我没有把 token 幂律指数与参数指数机械解释为和为 1 的
Chinchilla 关系。

### 2.2 拟合口径敏感性

第五档的宽平台使“怎样选每档最优点”成为主要模型不确定性。三种合理口径的结果如下：

| 最优点口径 | 参数幂律指数 | `N_opt(1e18)` | `N_opt(1e19)` |
| --- | ---: | ---: | ---: |
| 选定连续点 | 0.507774 | 56.65M | 182.4M |
| 各档全局二次拟合 | 0.583504 | 72.10M | 276.3M |
| 各档离散最低点 | 0.525898 | 70.85M | 237.8M |

在观测区间附近，这些方法仍较接近；外推到 `1e19 FLOPs` 后范围扩大到 182M--276M。
选定连续点的 leave-one-profile-out 范围更宽，约为 79M--263M。这表明最终参数规模并非由
一个高置信度指数唯一决定，最终候选应同时考虑可运行性和已有架构验证。

### 2.3 最优 loss 外推

我对每档的连续最小 loss 比较了两种低自由度模型：

$$
L_{\text{floor}}(C)=3.838745+5.489412\,C^{-0.131660},
$$

以及

$$
L_{0}(C)=9.393324\,C^{-0.080073}.
$$

两者在五个 profile 上的 RMSE 分别为 0.08569 和 0.10785。在最终候选对应的约
`1.048e19 FLOPs` 处，两种全数据拟合分别预测 6.03585 和 5.38223。点预测取二者中点并
按提交精度记为 **5.71**，以避免只选择更乐观的函数形式。

leave-one-profile-out 后，带 floor 模型在目标算力处给出 `[5.5835, 6.7579]`，零 floor
模型给出 `[5.2284, 5.4433]`。我用两类模型与 profile 选择敏感性的联合包络，形成最终提交
区间 **[5.23, 6.76]**。该区间被用作课程要求的 80% 中心预测区间的操作性近似，但它不是
由独立重复实验校准得到的频率学 80% 覆盖区间；它主要表达函数形式、profile 选择和远距离
外推的不确定性。

### 2.4 Wall-clock 与最终超参数验证

使用 25 个不短于 100 秒的完成运行拟合经验运行时间：

$$
t=\exp(-21.335431)\,C^{1.049835}P_{\text{total}}^{-0.656785}.
$$

该模型 log-space $R^2=0.989768$，leave-one-out 中位绝对百分比误差为 7.23%，P90
欠预测倍率为 1.151。加入 batch、层数和宽度后的诊断模型将留一法中位误差降至 4.99%，
但这些特征高度相关，所以只把它用于风险诊断，不把各指数解释为因果效应。

高计算锚点 `exp-000377` 的预测用时约 7,134 秒，却在 9,000 秒上限处仍未完成。这条失败
结果没有 loss，不能进入 scaling-law 拟合，但它说明短运行模型会低估长运行或平台波动，
最终配置必须留出明显时间余量。

最后六个实验用于直接比较 batch 和 peak LR：

| 实验 | 模型 | Batch | Peak LR | Tokens | Final loss | Runtime |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `exp-000477` | L8/d512 | 16 | `3.2e-3` | 67.109M | 8.837646 | 493s |
| `exp-000479` | L8/d512 | 32 | `3.2e-3` | 67.109M | 8.774902 | 460s |
| `exp-000480` | L8/d512 | 16 | `4.0e-3` | 67.109M | 8.837158 | 529s |
| `exp-000485` | L14/d1056 | 16 | `3.2e-3` | 113.443M | 8.326660 | 2,344s |
| `exp-000489` | L14/d1056 | 32 | `3.2e-3` | 113.508M | 8.124023 | 2,060s |
| `exp-000491` | L14/d1056 | 32 | `4.0e-3` | 113.508M | 8.255371 | 2,053s |

在代理模型和最终架构上，batch 32 都比 batch 16 更快且 loss 更低；在最终架构、batch 32
下，`4.0e-3` 比 `3.2e-3` 差 0.13135，因此最终选择 batch 32 和 peak LR `3.2e-3`。
这些短程运行的四个 validation loss 均保持下降，提供了局部稳定性证据，但不能替代完整
7.260B-token 训练。

## 3. 最终配置与预测

### 3.1 最终配置摘要

| 项目 | 取值 |
| --- | ---: |
| Transformer 层数 | 14 |
| Hidden size | 1056 |
| Attention heads / head dim | 11 / 96 |
| MLP intermediate size | 4224 |
| 非 embedding 参数 | 187.373M |
| 总参数 | 240.630M |
| Sequence length | 1024 |
| Train tokens | 7.260B |
| Train / validation batch size | 32 / 2 |
| Optimizer | AdamW |
| Peak learning rate | `3.2e-3` |
| Schedule | cosine，5% warmup，final LR fraction 0.1 |
| Weight decay / gradient clip | 0.01 / 1.0 |
| Validation evaluations | 4 |

该配置约对应 `1.048e19 FLOPs`。参数量接近选定参数幂律在目标计算量处的中心预测，并采用
已经短程验证的架构、batch 和学习率。同架构 batch-32 实验处理 113.508M tokens 用时
2,060 秒；按 token 数线性估计，完整训练约需 36.6 小时，相对 48 小时限制保留约 24%
余量。这个估计仍可能受到长运行吞吐漂移和平台开销影响。

### 3.2 最终预测

- 最终 loss 点预测：**5.71**
- 提交的预测区间：**[5.23, 6.76]**
- 区间依据：两种 loss 函数形式的差异，与 leave-one-profile-out profile 选择敏感性的联合
  包络；区间是不对称的，因为带不可约 floor 的模型主要扩展上侧风险，而零 floor 模型主要
  决定下界。
- 一致性：本报告中的模型、训练配置、点预测和上下界与最后一次本地保存并经 API GET 核对的
  provisional v3 记录一致；当时记录尚未冻结。

## 4. 局限性与风险

1. **外推距离长。** 最高完成的 IsoFLOPs 档约为 `1.034e17 FLOPs`，最终配置约为
   `1.048e19 FLOPs`，跨越约 100 倍计算量；高计算锚点又没有完成。
2. **第五档谷底被删失。** 20M--32M 参数附近 loss 很平，离散最低点仍在右边界；不同最优点
   口径会显著改变最终参数预测。
3. **区间没有独立校准。** `[5.23, 6.76]` 包含模型形式和 profile 选择风险，但缺少重复种子、
   held-out residual 或 posterior predictive calibration，不能证明精确的事前覆盖率。
4. **运行时间不是保证。** 高计算锚点暴露过至少 26% 的欠预测，完整训练仍可能受到长运行
   吞吐、验证开销和平台波动影响。
5. **稳定性验证较短。** 最终架构只直接运行了约 113.5M tokens，约为最终 token 数的 1/64；
   `3.2e-3` 在短程优于 `4.0e-3`，但没有验证完整 cosine 训练中的全程行为。
6. **探索与最终评测存在差异。** 探索 validation loss 不能完全校准集中评测的 held-out
   final loss；最终配置只运行一次，随机初始化和评测差异没有通过重复实验估计。

因此，这一最终配置应理解为“五个完成 profile 的中心外推 + 经过短程验证的保守可运行候选”，
而不是已经由高算力实验确认的唯一最优解。
