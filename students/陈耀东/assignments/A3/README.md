## 2. 实验历程与设计逻辑

我没有把其他同学的结果作为拟合数据或决策依据，实验顺序由自己的观测逐步决定：

1. **小规模网格（S/T/U）**：先固定训练规则，改变模型规模和 token 数，确认 loss 随两者增加而下降，并用重复配置观察随机种子差异。
2. **激进扩展（V）**：把模型扩大到约 51M、124M 和 253M 参数，并在 16.8M、67.1M、134.2M token 处取点，检验趋势能否进入更大的 N、D 区间。
3. **恢复实验（V5R/V6R）**：原 V5 多次验证导致超时，因此保留模型、token 和学习率，只把 `num_evals` 改为 1 重跑，区分“训练本身不足”和“验证开销过大”。V6R 完成后证明在 253M 模型上继续增加 token 仍有收益。
4. **优化设置校准（W0、W1、R1）**：W0 测试约 124M 模型在 batch=8、学习率 `3e-4` 下的表现；W1 保持约 51M 模型和长 token 但 batch=8，最终超时；R1 将同一 51M/393.2M 配置改为 batch=16，并完成长 token 校准。
5. **桥接实验**：约 81M 参数、229.4M token、batch=16 的桥接运行超时，只留下中间 loss，因此不把它当作最终拟合点。

这个顺序的核心判断是：先确认 N、D 的单调趋势，再把预算用于扩大有效观测范围，最后用一个真实完成的长 token、batch=16 运行校准最终配置。每次失败都保留为失败证据，不用部分结果伪装成 completed 终点。

| V1 | 51.0M | 67.1M | 2 | `2e-4` | 11.5039 | 905 | 参数量/ token 扩展 |
| V2 | 123.7M | 16.8M | 2 | `1.5e-4` | 12.9453 | 489 | 大模型低数据量对照 |

## 4. Scaling-law 拟合与诊断

### 4.1 主模型

计算量用近似关系表示：

$$
C \approx 6ND,
$$

其中 $N$ 是参数量，$D$ 是训练 token 数。主拟合使用 24 个 `batch=2` 且完整结束的观测，以非嵌入参数量作为模型规模变量：

$$
L(N,D)=L_\infty
+a\left(\frac{N_{\mathrm{nonembed}}}{10^8}\right)^{-\alpha}
+b\left(\frac{D}{10^8}\right)^{-\beta}.
$$

对 $\alpha$、$\beta$ 做网格搜索；给定指数后，用最小二乘求线性系数 $L_\infty,a,b$。选择非嵌入参数是因为题面给出的近似正是

$$
N_{\mathrm{nonembed}}\approx 12n_{\mathrm{layer}}d_{\mathrm{model}}^2.
$$

主拟合得到 $\alpha=0.20$、$\beta=0.03$，RMSE 为 **0.3611**。残差均值接近 0，样本标准差约 **0.3689**，残差绝对值中位数约 **0.2939**。总参数量拟合作为敏感性对照，结论没有改变。较大的 token 指数不应被过度解读：当前实验的 token 范围仍有限，而且优化设置并不完全正交。

### 4.2 Token 轴与 batch 校准

对 51M 模型的 4 个 `batch=2`、学习率 `2e-4` 完整点单独拟合：

$$
L(D)=c+k\left(\frac{D}{10^8}\right)^{-\beta}.
$$

该 token 轴拟合的 $\beta=0.31$，RMSE 约 **0.0109**。在 R1 的 393.2M token 处，token 轴给出的 batch=2 基线约为 10.4500，而 R1 实测为 9.0903，差异约 **1.3597 loss**。这只能被解释为 batch=16 与学习率 `3e-4` 的联合校准收益，不能声称已经单独识别了 batch 或学习率的因果效应。

## 5. 最终配置与预测

### 5.1 选择的最终配置

最终候选沿用 R1 已验证的结构和优化设置：

| 项目 | 值 |
|---|---|
| 模型结构 | 8 层，hidden size 512，8 个 attention heads，head dimension 64 |
| FFN 中间层 | 2,048 |
| 参数量 | 总参数约 50,995,712；非嵌入参数约 25,174,528 |
| 训练 batch | 16；验证 batch 4 |
| 训练 token | 20,919,844,864（按 32,768 对齐） |
| 优化器 | AdamW |
| 学习率 | `3e-4`，cosine schedule |
| warmup / final LR fraction | `0.05` / `0.1` |
| weight decay | `0.01` |
| seed | 0 |
| 其他 | `sequence_length=1024`，`num_evals=2`，梯度裁剪 1.0，`bfloat16` |

非嵌入参数的题面近似为：

$$
12\times 8\times 512^2=25,165,824,
$$

与 API 更完整的估计值略有差异，原因是后者还包含具体实现中的非嵌入模块参数。最终候选对应约 $6.40\times 10^{18}$ FLOPs 的 48 小时计算预算外推。

### 5.2 点预测与预测区间

- **最终验证 loss 点预测：8.0677**
- **80% 中央预测区间：[7.2677, 8.8677]**

点预测来自 token 轴在 20.9B token 处的外推，再加上 R1 的 batch/学习率联合校准。区间综合了 token 轴拟合误差、联合校准误差和从探索区间外推到 48 小时的距离；它是预测不确定性，不是 `validation_losses` 历史，也不是已经完成的最终训练结果。

## 6. 局限性与外推风险

- batch=16 只有 R1 一个长 token 校准点，缺少同规模、同 token 的独立学习率和 batch 消融。
- 最终候选没有重复 seed，无法从当前实验估计完整的随机性分布。
- 参数量、token 数、batch 和学习率在部分实验中同时变化，主拟合描述趋势但不等同于因果识别。
- 48 小时 token 数远高于探索区间，吞吐率外推可能受到调度、验证和系统状态影响。
- 探索验证集与最终 held-out 评测之间可能存在分布差异；预测区间因此不能保证覆盖隐藏评测结果。

因此，我把 8.0677 视为有实验依据的工作预测，而不是确定的最优定理。停止探索的依据是边际信息量已经低于新增预算风险：剩余 3,408 秒既不足以完成有意义的长 token 轴，也不足以同时拆分 batch 与学习率影响。
